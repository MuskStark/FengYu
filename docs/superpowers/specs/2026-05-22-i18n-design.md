# i18n Design Spec

## Goal

Add internationalization to SwissKitJ with English as the default language and Chinese as a supported locale. Live locale switching (no restart). Built-in tools fully translated. Plugin i18n via the API module.

## API: `fan.summer.api.i18n.I18n`

A singleton in `SwissKitJ-Api`:

```java
public final class I18n {
    // Core lookup
    static String get(String key);
    static String get(String key, Object... args);

    // JavaFX reactive binding — updates the property on every locale switch
    static VoidBinding bind(StringProperty property, String key);
    static VoidBinding bind(StringProperty property, String key, Object... args);

    // Locale management
    static Locale getLocale();
    static void setLocale(Locale locale);

    // Listener for manual refresh
    static void addListener(Runnable listener);
    static void removeListener(Runnable listener);

    // Bundle registration (host + plugins)
    static void registerBundle(String baseName, ClassLoader loader);
    static void unregisterBundle(String baseName);
}
```

- Default locale: `Locale.ENGLISH`
- `setLocale()` rebuilds bundles, updates all bindings via `Platform.runLater()`, fires listeners
- `registerBundle()` merges a plugin's bundle into the lookup chain (plugin bundles checked after host)
- Missing keys fall back to the key itself
- Thread-safe reads via `AtomicReference<ResourceBundle>` snapshot

## Internal Helper: `fan.summer.api.i18n.BoundEntry`

Tracks a `StringProperty` + key + `VoidBinding` so `I18n` can batch-update all bound properties on locale switch. Disposed on plugin unload.

## Resource Bundle Structure

**Host bundles** (`SwissKit/src/main/resources/i18n/`):

| File | Purpose |
|------|---------|
| `messages.properties` | English (default, fallback) |
| `messages_zh.properties` | Chinese |

The existing `messages_en.properties` is deleted — English IS the default.

**Plugin convention:** Plugins include `i18n/messages.properties` (English) and optionally `i18n/messages_zh.properties` in their JAR. The host discovers these when loading the plugin and registers them via `I18n.registerBundle("i18n.messages", pluginClassLoader)`.

## Key Naming

Flat keys with dot-separated prefixes. Examples:

```
# Shell
app.name=SwissKitJ
sidebar.section.tools=TOOLS
sidebar.label.aiChat=AI Chat
sidebar.label.settings=Settings

# Detail panel
detail.btn.launch=Launch Tool
detail.category.dev=Developer Tools

# Settings
setting.general.title=General Settings
setting.email.smtpServer=SMTP Server

# Built-in tools
builtin.base64.name=Base64
builtin.base64.desc=Base64 Encode / Decode
builtin.email.name=Email Sender

# Plugin Store
store.online.title=Plugin Store
store.local.title=Install from Local File
```

## Live Switching Mechanism

`setLocale()` triggers:

1. Rebuild host `ResourceBundle` for the new locale
2. Rebuild all plugin bundles for the new locale
3. Snapshot merged bundle into `AtomicReference`
4. Invalidate all `BoundEntry` bindings → each `StringProperty` updates via `Platform.runLater()`
5. Fire all `Runnable` listeners via `Platform.runLater()`

**ContentArea** registers a listener calling `refresh()`, which rebuilds all `ToolCard` instances. Each card calls `plugin.getName()` / `plugin.getDescription()` again, getting the new locale's strings.

**DetailPanel** registers a listener that re-calls `fillData(currentPlugin)` if the panel is open.

## Built-in Tool Integration

No changes to `SwissKitJPlugin` interface. Built-in plugins use `I18n.get()` in metadata methods:

```java
@Override public String getName()        { return I18n.get("builtin.base64.name"); }
@Override public String getDescription() { return I18n.get("builtin.base64.desc"); }
```

Internal UI strings within `createView()` use `I18n.bind()` for live updates:

```java
Label smtpLabel = new Label();
I18n.bind(smtpLabel.textProperty(), "setting.email.smtpServer");
```

External plugins that want i18n register their own bundle and follow the same pattern.

## Initialization

In `SwissKitJApp.start()`, after `DatabaseInit` and before UI construction:

```java
I18n.registerBundle("i18n.messages", getClass().getClassLoader());
String savedLang = readLanguageFromDb();
if ("zh".equals(savedLang)) I18n.setLocale(Locale.CHINESE);
```

## PluginLoader Integration

When `PluginLoader` loads a plugin JAR:

```java
URL bundleUrl = classLoader.getResource("i18n/messages.properties");
if (bundleUrl != null) {
    I18n.registerBundle("i18n.messages", pluginClassLoader);
}
```

On plugin unload, `I18n.unregisterBundle("i18n.messages")` is called to remove its keys and dispose its bindings.

## Settings UI Change

The language combo box in General Settings now calls `I18n.setLocale()` directly instead of just saving to DB. It still persists the choice to DB so it can be restored on next launch. The "Restart may be required" toast is removed since switching is now live.

# Internationalization

The host owns the locale and pushes it to every plugin; a plugin never ships its own language switcher. The current locale travels on the `Environment` object the SDK delivers to the iframe, and the host notifies the plugin when it changes.

## Reading the locale

`FengYuClient.ready()` resolves with an `Environment` whose `locale` field holds the active locale tag (e.g. `en`, `zh-CN`):

```js
import { fengyu } from './sdk.js'

const env = await fengyu.ready()
console.log(env.locale)   // → 'zh-CN'
```

`ready()` also applies the locale to the document — `document.documentElement.lang` is set to `env.locale` — so any locale-aware CSS or attribute selector works without extra wiring.

## Responding to changes

If the user switches language while the plugin is open, the host emits an `environment` event. Subscribe with `client.on('environment', handler)`:

```js
const off = fengyu.on('environment', (env) => {
  applyLocale(env.locale)
})
// ...later, on teardown
off()
```

The handler receives the full updated `Environment`, so re-read `env.locale` (and `env.theme`) and re-render.

## Recommended approach

The host does not translate plugin strings — that is the plugin's responsibility. The recommended pattern is to **bundle your own message tables keyed by locale** and select on `Environment.locale`:

```js
const messages = {
  'en':    { title: 'Split complete', pick: 'Choose a file' },
  'zh-CN': { title: '拆分完成',         pick: '选择文件' }
}

function t(key) {
  const locale = currentLocale.startsWith('zh') ? 'zh-CN' : 'en'
  return messages[locale][key] ?? messages['en'][key] ?? key
}
```

Fall back to a default locale (typically `en`) when the active locale has no translation. Because the host sets `document.documentElement.lang`, you can also read the locale from the DOM at any time as a fallback:

```js
const locale = document.documentElement.lang  // 'en' | 'zh-CN' | ...
```

::: warning
Do not add a language switcher to your plugin UI. The host is the single source of truth for locale; a plugin-level switcher would desync from the rest of the app.
:::
